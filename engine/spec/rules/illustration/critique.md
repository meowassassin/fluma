# 그림 비평 루브릭 (open-design `critique` 를 그림용으로)

`python3 engine/craft/draw.py critique <form.json> --style <style.json> --ref <참고 영상 id>` 가 비평용 한 장 · lint · 숫자를 내고 빈 평가지를 만든다.
비평자는 **비평용 한 장을 실제로 보고** 다섯 기준에 점수를 매긴다. 기준끼리 평균 내서 흥미로운 실패를 감추지 않는다.

## 점수 띠
0–4 **망가짐** · 5–6 **동작함(초딩 티)** · 7–8 **탄탄함** · 9–10 **뛰어남**

## 다섯 기준

### 1. 화풍 일치 (레퍼런스 칸과 나란히)
- 팔레트 · 명도 구조 · 외곽선 유무 · 명암 단계가 레퍼런스와 같은 계열인가.
- 형태의 둥글기 · 단순함 수준이 같은가(레퍼런스보다 잔손질이 많거나 투박하면 감점).
- 근거: `style_match` 의 bright · sat · palette_dist, 칸끼리 눈으로 비교한 차이 한 줄.

### 2. 실루엣 (검은 칸)
- 까맣게 칠해도 무엇이 무엇을 하는지 읽히는가(행동까지).
- 팔 · 소품 · 특징이 몸 실루엣 밖으로 나와 있는가. 감자 모양 · 접선 · 애매한 덩어리(모자인지 보따리인지 모를 것)는 감점.

### 3. 매력 (컬러 칸)
- 도형 언어가 성격과 맞는가(주인공 둥글게 · 악당 뾰족하게).
- 비율 · 표정 · 몸짓(동세선)이 살아 있는가. 차렷 자세 · 멍한 눈동자 · 표정 없음은 감점.

### 4. 디테일 · 완성도 (컬러 칸 + 엄지손톱 칸)
- 크기 위계(큰 · 중간 · 작은)와 쉬는 면이 있는가. 디테일이 작은 덩어리에 모였는가.
- 엄지손톱 크기에서 핵심(얼굴 · 행동)이 읽히는가. 부품끼리 어색하게 겹치거나 묻히거나 떠 있으면 감점.

### 5. 명도 (흑백 칸)
- 밝음 · 중간 · 어둠 세 덩어리로 나뉘는가. 주인공이 배경에서 떨어져 보이는가.
- 겹친 부품끼리 밝기가 같아 묻힌 곳이 없는가(lint I10 과 같이 본다).

## 결과 형식 (평가지 JSON 에 채운다)
```json
{ "scores": { "style": 6, "silhouette": 7, "appeal": 5, "detail": 5, "value": 6 },
  "evidence": { "style": "…", "silhouette": "…", "appeal": "…", "detail": "…", "value": "…" },
  "keep": ["…"], "fix": ["P0 …", "P1 …"], "quick": ["…"],
  "changes": ["형태에서 바꿀 것 — 관계 · 비율 · 역할 색으로(좌표 금지)"] }
```

## 고리
1. 평가지를 채운다 → `changes` 대로 형태 · 화풍 카드를 고친다 → 다시 `critique`.
2. **멈춤 조건**: 모든 기준 7 이상 + lint P0 · P1 없음. 또는 3회.
3. 3회 뒤에도 7 미만인 기준이 있으면 숫자 그대로 사용자에게 말한다("매력 5 — 표정 부품이 부족, 엔진이 지원하지 않는 X 필요"). 엔진 한계면 무엇이 필요한지 적는다.
4. 회차마다 `<form>.critique.jsonl` 에 점수가 쌓인다 — 사용자에게는 회차별 점수를 보여 준다.
