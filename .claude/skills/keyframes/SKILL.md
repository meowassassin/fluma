# 3단계 — 샷별 키 프레임 · 승인 ②

조건: 1단계 샷 계획이 `plan.py check` 통과, 캐릭터가 나오면 그 캐릭터 시트가 승인 ①(`character.py status` 가 '승인').
Veo · Flow 는 시작 프레임과 캐릭터 참조를 한 번에 받지 못한다 — 그래서 캐릭터 일관성은 이 단계에서 시트를 참조로 그림 안에 넣어 잡는다(사용자 결정 2026-11-11).

> 작업 공간 화면 **/pipeline/<id>** 에서 사용자가 그림 · 클립을 보고 승인 · 재생성 버튼을 누를 수 있다 — 대화에서는 그 화면을 안내하고, 사용자가 대화로 승인을 말하면 명령으로 기록한다.

## 순서
1. `python3 engine/gen/keyframe.py make <id>` — 샷마다 시작 프레임(그 샷 각도에 가까운 시트 그림 + 정면을 참조로), `end_frame: true` 인 샷은 끝 프레임도(시작 프레임을 참조로 끝 상태만 다르게). 세 장씩 동시에, 한 장 약 1분.
   샷 하나를 여러 장 보고 고르려면 `--shots 3 --candidates 3` → `pick <id> 3 <번호>`.
2. 승인용 그림 `data/compositions/<id>/keyframes/sheet.png` 를 먼저 직접 열어(`read_file` / `Read`) 확인한 뒤 사용자에게 보여 준다. 확인할 것:
   - **주제 직관성 · 서사 진행(가장 중요)**: 소리를 끄고 시트의 그림만 순서대로 봐도 **영상의 주제(예: 브라우저 창, 마우스 커서, RAM 슬롯, USB 단자 등 구체적 사물)와 기승전결(원인→과정→위기→해결)이 한눈에 읽히는가?** 만약 주제를 알 수 없는 추상적인 구슬/배경으로 그려졌거나 앞뒤 샷이 똑같은 구도·상황을 반복한다면 그대로 승인 요청하지 말고 1단계 샷 칸(`start_state` · `background`)을 구체적 사물로 고쳐 다시 만든다.
   - **시각 일관성 · 기술 품질**: 화풍이 샷끼리 같은가 · 캐릭터 얼굴 · 옷이 시트와 같은가 · 구도(샷 크기 · 앵글 · 화면 안 위치)가 계획대로인가 · 아래 1/5 에 중요한 것이 없는가 · 글자가 없는가 · 끝 프레임이 시작과 같은 장면에서 바뀐 것 하나뿐인가.
3. 선택지: 샷별 승인 / 그 샷만 다시(`make --shots 2`) / 샷 칸 고치기(1단계 샷 계획 — 고치면 그 샷 승인은 자동 무효) / 화풍 고치기(style — 모든 샷 다시).
4. 사용자가 승인한 샷만 `python3 engine/gen/keyframe.py approve <id> --shots 1,2`. 승인은 프롬프트 · 참조 · 그림 해시에 묶인다.
5. 모든 샷이 승인되면(`status`) 4단계 영상 생성으로 갈지 묻는다. **영상 생성은 승인 ②를 마친 샷만**(스펙 4장).

## 하지 않는 것
- 사용자 승인 없이 approve 하지 않는다. 2단계와 합치지 않는다.
- 실패하면 자동으로 계속 다시 부르지 않는다 — 보고하고 사용자와 정한다.
- 키 프레임에 글자를 넣지 않는다(글자는 5단계 편집에서).
