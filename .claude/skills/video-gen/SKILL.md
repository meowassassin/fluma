# 4단계 — 영상 생성 · 샷 검토

조건: 3단계 키 프레임이 모두 승인 ②(`keyframe.py status`). 승인 안 된 샷은 만들지 않는다.
입력: 1단계 샷 칸에서 조립한 움직임 프롬프트 + 시작 프레임(승인 키 프레임) [+ 끝 프레임]. 캐릭터 시트는 넘기지 않는다(키 프레임에 이미 그려져 있음 — Veo · Flow 는 시작 프레임과 참조를 같이 못 받는다).

> 작업 공간 화면 **/pipeline/<id>** 에서 사용자가 그림 · 클립을 보고 승인 · 재생성 버튼을 누를 수 있다 — 대화에서는 그 화면을 안내하고, 사용자가 대화로 승인을 말하면 명령으로 기록한다.

## 순서
1. 모델: 설정 `data/workspace/settings.json` 의 `videogen.model` 을 사용자가 고른다(`tools/gflow/.venv/bin/gflow models --json` 목록, 비용은 `videogen.credits` — 기본값은 Flow 도움말). **안 골랐으면 시작하지 않는다.**
2. `python3 engine/gen/video.py plan <id>` — 경로 · 필요 크레딧(샷 수 × 샷당 비용) · 잔액(크레딧 안 씀). 잔액이 충분하면 영상 전체를 경로 B, 부족하면 영상 전체를 경로 A — 경로 A 로 바뀌면 사용자에게 알린다.
3. `python3 engine/gen/video.py run <id>` — 샷마다 제출 전에 시도 기록을 쓰고 생성. 실패하면 멈춘다:
   - 진행 중 크레딧 부족 → 남은 샷을 경로 A 로 넘기지 않고 사용자에게 묻는다(경로가 섞이면 화풍이 흔들린다).
   - 계정 잠금(Error 253 등) · 도구 고장 → 보고. 다른 경로로 자동 전환하지 않는다(사용자가 확인한 경우에만 수동으로 `--backend antigravity`).
   - 결과를 모름(indeterminate) → 다시 제출하지 않는다(크레딧이 이미 빠졌을 수 있음). Flow 프로젝트에서 회수할지 사용자와 정한다.
4. 샷 검토: 생성된 클립(`data/compositions/<id>/clips/sNN/takeK.mp4`)의 정지 화면(`preview.py` 또는 `look.py sheet`)을 먼저 직접 열어 확인하고 클립을 보여 준다(모션은 미리 승인받지 않는다).
   - **검토 기준**: ① 시작 프레임의 캐릭터 · 화풍이 깨지지 않고 이어지는가 ② 샷의 핵심 동작과 주제 사물(예: 창이 쏟아짐, 슬롯에 꽂음, 로딩 링이 돎, 닫기 버튼을 누름)이 나레이션과 어울리게 표현되었는가 ③ 불필요한 깨진 글자 · 기괴한 변형이 없는가.
   - 통과한 샷은 `approve <id> --shots 1,3`, 마음에 안 드는 샷만 `run <id> --shots 2`(크레딧 확인부터 다시).
4-1. **말로 고치기**: 사용자가 "글자 더 크게" 같은 말을 하면 영어로 옮겨 `python3 engine/gen/video.py revise <id> --shots 2 --say "Make the text bigger"` → `run <id> --shots 2`. 모션그래픽 샷은 같은 Flow 프로젝트의 지난 테이크(`flow_media_id`, `@` 멘션)나 클립을 레퍼런스로 함께 붙여 나머지는 그대로 두게 한다(화면의 '고치기' 칸도 같은 명령).
5. 재생성은 샷당 최대 3회(두 경로 합산). 상한이면 더 만들지 않고 프롬프트(1단계 샷 칸) 또는 시작 프레임(3단계)을 사용자와 고친 뒤 다시 — 입력이 바뀌면 횟수를 새로 센다.
6. 모든 샷이 통과하면 5단계(편집 · 자막 · 나레이션)로 갈지 묻는다.

## gflow-cli(경로 B) 규칙 — 비공식 도구, 계정 잠금 위험
- 전용 Google 계정만(개인 메인 계정 금지). 로그인은 사용자가 직접: `! tools/gflow/.venv/bin/gflow auth login --browser chrome`.
- 시험은 `gflow mcp run --no-spend`(과금 도구가 등록되지 않음). 크롬이 뜨는 로컬에서만 동작.
- 오류가 나면 비공식 우회를 새로 만들지 않고 보고한다. 무한 재시도 · 폴링 금지(모든 호출에 시간 상한).
- `--backend mock` 은 개발자 흐름 시험 전용(키 프레임 한 장을 늘린 정지 화면) — 경로가 막혔을 때 대안으로 **추천하지 않는다**. 사용자가 고르면 "실제 영상이 아니다"를 먼저 말하고, mock 이 남은 영상은 최종 렌더 · 업로드가 막힌다.
- 두 경로가 다 막히면 막힌 이유와 풀 방법(gflow 재로그인 · 다른 계정 · 시작 프레임 없이 t2v)만 보고하고 멈춘다.
- 시작 프레임은 승인 ②를 받은 키 프레임(`sNN.png`)뿐 — 3D 무대(`_stage`) · 캔버스(`_compose`)는 키 프레임을 만들 때 구도 참고일 뿐 시작 프레임이 아니다.
